# 多账号界面与 API 隔离

本分支保留 CloudCLI 现有的单机运行方式。首次注册的账号是管理员；管理员在「设置 → 用户」创建其他账号。新账号使用独立登录凭据，只能在项目列表、会话列表、历史、实时聊天及相关项目 API 中看到自己的记录。现有数据库中的项目和会话在迁移时归给首次注册的账号，旧附件也只由该账号读取。

归属字段存于 `projects.owner_user_id` 和 `sessions.owner_user_id`。项目、会话、草稿、定时消息、上传附件、聊天 WebSocket、项目文件、Git、TaskMaster 和 Worktree 的 HTTP 入口按登录账号校验。新建 Worktree 项目继承请求账号。平台模式使用单一代理身份，无法区分账号，因此不提供创建账号的入口。

这只是应用层隔离。所有账号仍运行于同一系统用户下，共用主机文件系统、CLI 登录状态、全局 Git 配置及部分机器级设置。文件系统浏览器和终端具备这个系统用户的权限；不要把此模式用于需要防止用户互相读取主机文件的场景。浏览器自动化是机器级资源，仅管理员可访问。一个项目路径目前只能注册给一个账号。

合并与部署时应先备份数据库，再运行现有构建与迁移流程。迁移只加字段、索引和附件归属表，不删除旧记录。此分支没有部署，也没有重启正在运行的单人版服务。
